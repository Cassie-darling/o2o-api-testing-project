## 2.1 地区级联数据（省/市/区）

| 要素     | 内容                                                                                                                                                                                                  |
| ------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| URL：   | GET /index.php/home/Index/json_area.html                                                                                                                                                            |
| 鉴权：    | 否                                                                                                                                                                                                   |
| 请求头：   | 无（query 传参）                                                                                                                                                                                         |
| 请求参数：  | src=cache、callback=cb（JSONP，前端固定带 `&callback=?`）                                                                                                                                                   |
| 返回数据：  | JSONP，包裹函数 `cb(...)`，数据结构：{"0":[[1,"北京"],[2,"天津"],[19,"广东"]...], "19":[[199,"广州"],[305,"东莞"]...], "305":[[3144,"东莞市"]...]}<br>key 为父级 area_id（"0"=省级列表），value 为 `[area_id, 名称]` 数组。一次性下发全量省市区（约 126KB），前端插件 `$.ds_region()` 本地级联。 |
| 配套接口：  | GET /index.php/home/Index/json_area_show?area_id={id}&callback=cb<br>返回 `cb({"text":" 东莞市"})`（id→名称，编辑回显用）；area_id=0 → `{"text":null}`。                                                              |

### 测试用例

**1、测试点分析**

数值：
	正向：
		- 省级列表查询：area_id=0，返回省级数据数组
		- 市级列表查询：area_id=19（广东），返回城市列表（广州/东莞等）
		- 区级列表查询：area_id=305（东莞），返回区县列表（东莞市）
		- 回显接口正常调用：area_id=3144，返回 `{"text":" 东莞市"}`
		- <span style="color:blue">全量数据完整性（台湾/港澳）</span>

	反向：
		- <span style="color:blue">area_id 越界</span>（如 999999，返回空数组或 null）
		- area_id 为负数（如 -1）
		- area_id=0 时回显接口返回 `{"text":null}`
		- <span style="color:blue">area_id 非数字</span>（如 abc，返回错误或空）
		- <span style="color:blue">area_id 注入</span>（如 `' OR 1=1 --`，无注入执行）

参数：
	正向：
		- src=cache + callback=cb 正常传参，返回 JSONP 格式数据
		- callback 参数正常解析，包裹函数名正确

	反向：
		- <span style="color:blue">JSONP 回调名自定义</span>（如 callback=alert(1)），验证是否允许任意回调名（XSS 风险）
		- src 参数缺失（是否仍返回数据或报错）
		- src 传非 cache 值（如 src=test）
		- callback 参数缺失（是否返回纯 JSON 或报错）
		- 无任何参数请求（裸请求）

业务：
	正向：
		- 前端 `$.ds_region()` 插件三级级联回显正确
		- 缓存命中：重复请求返回相同数据
		- <span style="color:blue">缓存头</span>验证（Cache-Control / ETag / Expires）

	反向：
		- 数据量约 126KB，验证大响应体传输完整性
		- 省市区层级关系一致性（子级 area_id 在父级列表中存在）

## 2.3 收货地址 - 新增

| 要素       | 内容                                                                   |
| -------- | -------------------------------------------------------------------- |
| URL：     | POST /index.php/home/memberaddress/add/o2o_errand_type/0.html        |
| 鉴权：      | 是                                                                    |
| Content-Type： | application/x-www-form-urlencoded                                    |
| 返回格式：    | AJAX JSON                                                            |

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| true_name | string | 是 | 收货人姓名 |
| city_id | int | 是 | 城市ID（东莞=305） |
| area_id | int | 是 | 末级区县ID（东莞市区=3144），需选到最后一级（checklast） |
| area_info | string | 是 | 地区全称，如"广东 东莞市 东莞市" |
| address | string | 是 | 详细地址 |
| tel_phone | string | 否 | 座机 |
| mob_phone | string | 是 | 手机号（11 位） |
| is_default | int | 否 | 1=默认地址 |
| longitude | decimal | 是* | 经度（百度地图选点，外卖配送范围/距离判定用） |
| latitude | decimal | 是* | 纬度 |

成功：`{"code":10000,"message":"保存成功","result":{"address_id":"55"}}`

### 测试用例

**1、测试点分析**

数值：
	正向：
		- 全部必填参数有效，正常新增地址，返回 `{"code":10000,"result":{"address_id":"55"}}`
		- is_default=1 设为默认地址
		- 可选参数 tel_phone 不传，新增成功
		- 经纬度有效值（如 longitude=113.75, latitude=23.05）

	反向：
		- <span style="color:blue">手机号格式</span>：非 11 位（10 位/12 位）
		- 手机号含非数字字符（如 1380013800a）
		- 手机号为空
		- <span style="color:blue">未选到区</span>（area_id 未选到最后一级，checklast 校验）
		- <span style="color:blue">经纬度缺失对配送范围的影响</span>（longitude/latitude 为空时地址可保存但配送距离无法计算）
		- <span style="color:blue">特殊字符</span>：true_name/address 含特殊字符（如 <>{}等）
		- 收货人姓名为空
		- 详细地址为空
		- area_info 为空

参数：
	正向：
		- 所有必填参数齐全且类型正确
		- 可选参数 tel_phone/is_default 不传

	反向：
		- 必填参数缺失（true_name/city_id/area_id/area_info/address/mob_phone 任一为空）
		- city_id 传非数字（如 abc）
		- area_id 传非数字
		- is_default 传非 0/1 的值（如 2）
		- 多余参数传入（服务端应忽略）

业务：
	正向：
		- <span style="color:blue">设为默认后原默认是否取消</span>（is_default=1 时，原默认地址自动改为非默认）

	反向：
		- <span style="color:blue">同会员地址上限</span>（达到上限后新增应失败，需确认上限值）

安全：
	正向：
		- 正常新增地址数据不含恶意字符

	反向：
		- area_info/address 字段含 SQL 注入（如 `' OR 1=1 --`）
		- true_name/address 字段含 XSS 脚本（如 `<script>alert(1)</script>`）

| 要素       | 内容                                                                  |

### 测试用例

**1、测试点分析**

数值：
	正向：
		- 删除自己的非默认地址，返回 `{"code":10000,"message":"删除成功"}`
		- 删除自己的默认地址（验证默认地址归属逻辑）

	反向：
		- <span style="color:blue">id 非法/不存在</span>（如 address_id=999999 或 abc）
		- address_id 为空

参数：
	正向：
		- 传入有效 address_id，正常删除

	反向：
		- address_id 缺失（URL 无 id 参数）
		- address_id 为空

业务：
	正向：
		- <span style="color:blue">删除默认地址后默认归属</span>（删除默认地址后是否自动指定其他地址为默认）

	反向：
		- <span style="color:blue">重复删除</span>（删除已删除的地址，应返回错误）
		- <span style="color:blue">删除被订单引用的地址</span>（地址被已有订单引用时是否允许删除）

安全：
	正向：
		- 仅能删除自己的地址

	反向：
		- <span style="color:blue">越权删他人地址</span>（篡改 address_id 为他人地址，应拒绝）
		- <span style="color:blue">id 篡改</span>（修改 URL 中的 address_id 尝试删除他人地址）
