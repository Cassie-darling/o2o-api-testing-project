### 3.2 附近商家列表（核心 JSON）

| 要素     | 内容                                                                                                                                                                                |
| ------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| URL：   | GET /index.php/home/Shopnearby/get_Own_Store_List                                                                                                                                 |
| 鉴权：    | 否                                                                                                                                                                                 |
| 请求头：   | 无（Query 传参）                                                                                                                                                                       |
| 请求参数：  | longitude（decimal，必填，定位经度）、latitude（decimal，必填，定位纬度）、storeclass_id（int，必填，店铺分类ID，0=全部分类）、page（int，非必填，滚动分页）                                                                      |
| 返回数据：  | JSON 数组（无 code 外层），按距离排序，元素字段：[{"store_id":9,"store_name":"吃饭啦","is_platform_store":0,"store_phone":null,"store_longitude":"106.559476","store_latitude":"29.556933","area_info":"重庆 重庆市 南岸区","store_address":"重庆市南岸区","store_logo":"http://.../default_store_logo.jpg","store_banner":null,"distance":0,"goods_list":[]}] |

### 测试用例

**1、测试点分析**

数值：
	正向：
		1、longitude + latitude + storeclass_id 必填正确，返回 JSON 数组，含 store_id/store_name/distance 等字段
		2、storeclass_id=0（全部分类），返回全部商家列表
		3、storeclass_id 指定有效分类，返回该分类下商家
		4、page 参数有效分页，返回对应页商家

	反向：
		1、longitude/latitude/storeclass_id 为空 + 其他正确
		2、longitude/latitude 越界（经度>180 或<-180，纬度>90 或<-90）+ 其他正确
		3、longitude/latitude/storeclass_id 含特殊字符（如 abc / !@#）+ 其他正确
		4、page 越界（如 page=9999，超出实际页数）
		5、storeclass_id 不存在（如 99999）
		6、坐标在无商家区域，返回空数组

参数：
	正向：
		1、四参数齐全且类型正确，GET 请求正常返回
		2、仅传必填三参数（不传 page），返回第一页数据

	反向：
		1、必填参数 longitude 缺失
		2、必填参数 latitude 缺失
		3、必填参数 storeclass_id 缺失
		2、longitude 传整数而非 decimal（如 106）
		3、storeclass_id 传负数（如 -1）
		4、page 传 0 或负数

业务：
	正向：
		1、返回列表按 distance 字段升序排序，距离最近的商家排第一
		2、is_platform_store=1 的平台自营店铺正常展示

	反向：
		1、下架/歇业/到期店铺是否从列表中过滤
		2、店铺无坐标（store_longitude/store_latitude 为空）时 distance 字段处理

安全：
	反向：
		1、longitude/latitude 参数 SQL 注入（如 `' OR 1=1 --`）
		2、storeclass_id 参数 SQL 注入

#### 3.5a 加入购物车

| 要素     | 内容                                                                   |
| ------ | -------------------------------------------------------------------- |
| URL：   | POST /index.php/home/cart/add.html                                   |
| 鉴权：    | 是（未登录/店主买本店会被拒）                                                      |
| 请求头：   | Cookie: PHPSESSID=xxx；Content-Type: application/x-www-form-urlencoded |
| 请求参数：  | goods_id（int，必填，商品ID）、quantity（int，必填，本次加入数量）、store_id（int，必填，店铺ID）  |
| 返回数据：  | 成功：`{"state":"true","num":1,"amount":"25.00"}`（num=购物车种类数，amount=合计金额）<br>重复加购：`{"state":"false"}`<br>店主买本店：`{"msg":"不能购买自己店铺的商品"}` |

### 测试用例

**1、测试点分析**

数值：
	正向：
		1、有效 goods_id + quantity=1 + store_id，返回 `{"state":"true","num":1,"amount":"25.00"}`
		2、quantity>1，加购成功，amount 为合计金额
		3、多规格商品传对应规格 SKU 的 goods_id，加购成功

	反向：
		1、quantity=0
		2、quantity 为负数
		3、quantity 超大数（如 999999）
		4、quantity>库存（如库存100，quantity=101）
		5、goods_id 不存在/已下架
		6、store_id 不存在

参数：
	正向：
		1、三参数齐全且类型正确，POST 正常返回 JSON

	反向：
		1、goods_id 缺失
		2、quantity 缺失
		3、store_id 缺失
		4、goods_id 传非数字（如 abc）
		5、quantity 传非数字
		6、store_id 传非数字

业务：
	正向：
		1、重复加购已在购物车的商品，返回 `{"state":"false"}`，数量以购物车为准

	反向：
		1、跨店加购不同店铺商品（验证多店铺购物车隔离）
		2、规格 goods_id 与普通 goods_id 混淆（多规格商品传 commonid 而非 SKU goods_id）

安全：
	反向：
		1、未登录加购（无 Cookie），应拒绝
		2、goods_id/store_id 参数 SQL 注入
		3、并发加购同一商品库存扣减一致性
