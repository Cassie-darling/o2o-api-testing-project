## 0. 设计说明

### 0.1 设计目标

以真实用户使用路径为主线串联接口，用最少的用例覆盖最多的接口，验证端到端业务链路的可用性与数据一致性。

### 0.2 业务场景用例要素

| 要素 | 说明 |
|---|---|
| 场景编号 | BIZ-001 ~ BIZ-007 |
| 场景名称 | 业务场景简称 |
| 角色 | 执行操作的用户角色（买家/商家/后台管理员） |
| 业务目标 | 用户通过该场景要达成的业务目的 |
| 前置条件 | 执行本场景前需满足的环境与数据条件 |
| 操作步骤 | 用户按业务逻辑顺序执行的操作序列 |
| 接口调用 | 每步操作对应的 API 请求 |
| 断言要点 | 每步操作后需验证的响应结果与业务状态 |
| 覆盖接口 | 本场景涉及的接口清单 |
| 场景价值 | 本场景能发现的缺陷类型与测试意义 |

### 0.3 场景总览

| 场景 | 角色 | 核心业务 | 覆盖接口数 |
|---|---|---|---|

## 11. 设计原则

1. **按用户真实使用路径串联**：每个场景都是用户在真实环境中会执行的操作序列，不是孤立调接口
2. **角色会话切换即测试鉴权**：BIZ-002和BIZ-003中买卖双方/后台的会话切换，隐含测试了Cookie-Session隔离和越权防护
3. **一条用例覆盖一个业务闭环**：BIZ-001覆盖"注册到下单"，BIZ-006覆盖"发码到新密码登录"，每个场景都是完整闭环而非半截
4. **异常场景独立设计**：BIZ-007专门针对下单失败的数据一致性和防重，因为这些只有跨接口才能发现
5. **已知缺陷融入场景**：BUG-1（下单阻断）直接写入BIZ-001和BIZ-007的预期结果，既测正向也测当前环境实际行为
6. **最少用例最多覆盖**：7条场景覆盖全部45个接口，平均每条场景覆盖6.4个接口，接口复用率高
