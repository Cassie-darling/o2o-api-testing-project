# 04.2 个人商家入驻（C2C）测试点分析

## 接口信息

| 要素 | 内容 |
|---|---|
| 模块 | 4.2 个人商家入驻（C2C，4步向导） |
| 测试类型 | 接口测试 |
| 鉴权 | 是（需会员登录态，Cookie-Session） |
| Content-Type | application/x-www-form-urlencoded |

### 等价类划分说明

| 等价类 | 包含参数 | 校验逻辑 | 测试策略 |
|---|---|---|---|
| 字符串文本类 | company_name, company_address, company_address_detail, contacts_name, business_licence_address | 非空+长度 | 空值每个都测；长度/注入选 company_name 作代表【抽样】 |
| 地区ID类 | province_id, city_id, district_id | 同一套地区查库校验 | 空值/非法值选 province_id 作代表【抽样】 |
| 坐标-经度 | longitude | 独立范围校验（-180~180） | 单独测 |
| 坐标-纬度 | latitude | 独立范围校验（-90~90） | 单独测 |
| 手机号 | contacts_phone | 独立正则校验（11位） | 单独测 |
| 邮箱 | contacts_email | 独立正则校验 | 单独测 |
| 执照号 | business_licence_number | 独立18位长度校验 | 单独测 |
| 日期-开始 | business_licence_start | 独立日期格式校验 | 单独测 |
| 日期-结束 | business_licence_end | 独立日期格式+逻辑校验（>start） | 单独测 |
| 非必填 | business_sphere | 无强制校验 | 测不传+超长 |

## Step1 店铺资质 → POST /index.php/home/sellerjoininc2c/step2.html

| 要素 | 内容 |
|---|---|
| URL | POST /index.php/home/sellerjoininc2c/step2.html |
| 鉴权 | 是 |
| 前置 | 会员已登录，GET step1.html 初始化入驻session |
| 返回 | dispatch_jump 跳转 step2 页面（HTML，非JSON） |

### 测试点分析

**数值正向：**
1. 全部15个必填参数正确提交，验证跳转step2成功，session写入资质数据
2. business_sphere 不传（非必填），验证提交成功
3. 坐标精度6位小数（106.559476, 29.556933），验证存储精度一致

**数值反向（必填参数为空，每个必填参数1条）：**
4. company_name 为空
5. company_address 为空
6. company_address_detail 为空
7. province_id 为空 → 【抽样代表地区ID类：province_id / city_id / district_id 走同一套地区校验逻辑，测一个代表即可】
8. longitude 为空
9. latitude 为空
10. contacts_name 为空
11. contacts_phone 为空
12. contacts_email 为空
13. business_licence_number 为空
14. business_licence_address 为空
15. business_licence_start 为空
16. business_licence_end 为空

**参数值非法（有独立校验逻辑的单独测）：**
17. province_id 传不存在的ID（如99999） → 【抽样代表地区ID类非法值】
18. province_id 传非数字（如abc） → 【抽样代表地区ID类类型错误】
19. longitude > 180（独立范围校验）
20. longitude 为负数且 < -180
21. latitude > 90（独立范围校验）
22. contacts_phone 格式错误：10位（少一位，独立正则）
23. contacts_phone 格式错误：12位（多一位）
24. contacts_email 格式错误：无 @ 符号（独立正则）
25. business_licence_number 17位（少一位，独立18位校验）
26. business_licence_number 19位（多一位）
27. business_licence_start 格式错误：非 YYYY-MM-DD（如 2024/01/01）
28. business_licence_end 早于 start（独立日期逻辑校验）

**参数缺失（抽样）：**
29. 完全不传 company_name 字段 → 【抽样代表参数缺失：后端 isset 检查走同一套逻辑，测一个代表即可】

**业务：**
30. 未登录直接 POST step2，验证重定向登录页
31. 未完成 GET step1 初始化直接 POST step2，验证 session 中无前置数据时拒绝
32. 坐标写入后后续商家端不可修改，验证 step1 写入的坐标持久化到最终店铺数据
33. 重复提交 step1（同一 session 提交两次），验证是否允许覆盖或拒绝

**安全：**
34. company_name 含 SQL 注入（' OR 1=1 --） → 【抽样代表字符串字段注入：全局防护，选一个代表】
35. company_name 含 XSS（`<script>alert(1)</script>`） → 【抽样代表字符串字段XSS】
36. 篡改 Cookie 越权提交他人入驻（用买家A的session提交B的入驻数据）

## Step3 店铺经营信息 → POST /index.php/home/sellerjoininc2c/step4.html

| 要素 | 内容 |
|---|---|
| URL | POST /index.php/home/sellerjoininc2c/step4.html |
| 鉴权 | 是 |
| 前置 | 已完成 Step1 + Step2（session中有资质+财务数据） |
| 返回 | dispatch_jump 提示"入驻申请已经提交，请等待管理员审核" |

### 参数独立校验逻辑说明

| 参数 | 独立校验逻辑 | 能否抽样 |
|---|---|---|
| seller_name | 与 session 中 step1 写入的账号做一致性比对 | 不能，单独测 |
| store_name | 查库做唯一性校验（不能与已有店铺重名） | 不能，单独测 |
| storegrade_id | 枚举值校验（只能 1/2/3） | 不能，单独测 |
| joinin_year | 枚举值校验（只能 1/2） | 不能，单独测 |
| storeclass_id | 查库做分类存在性校验（只能 1-8） | 不能，单独测 |
| store_class | 与 storeclass_id 做联动一致性校验 | 不能，单独测 |

**6 个参数 6 套不同的校验逻辑，没有一个能省。**

### 测试点分析

**数值正向：**
1. 全部6个参数正确提交（storegrade_id=1, joinin_year=1, storeclass_id=7, store_class=7），验证提示"入驻申请已提交"
2. storegrade_id 选白金（=2），验证各等级均可选
3. storegrade_id 选钻石（=3），验证各等级均可选
4. joinin_year 选2年，验证各年限均可选
5. 选有下级类目的分类时 store_class 传末级ID，验证联动逻辑

**数值反向（必填参数为空，每个必填参数1条）：**
6. seller_name 为空
7. store_name 为空
8. storegrade_id 为空
9. joinin_year 为空
10. storeclass_id 为空
11. store_class 为空（隐藏域未传）

**参数值非法（6个参数都有独立校验逻辑，不能抽样）：**
12. seller_name 与 step1 提交的不一致（独立一致性校验）
13. store_name 与已有店铺重名（独立唯一性校验）
14. storegrade_id 传非枚举值 4（独立枚举校验，越界）
15. joinin_year 传非枚举值 3（独立枚举校验，越界）
16. storeclass_id 传不存在的值 99（独立存在性校验）
17. store_class 与 storeclass_id 不联动（如 storeclass_id=7 但 store_class=3）（独立联动校验）
18. storeclass_id 传非数字（如 abc） → 【抽样代表ID类型错误：storeclass_id 和 store_class 都是int类型，测一个代表】

**参数缺失（抽样）：**
19. 完全不传 storegrade_id 字段 → 【抽样代表参数缺失】

**业务：**
20. 未完成 Step1/Step2 直接 POST step4，验证 session 中无前置数据时拒绝
21. 跳过 Step2（完成 Step1 但未走 Step2）直接 POST step4，验证拦截
22. Step4 重复提交（同一 session 提交两次），验证不产生重复申请
23. 保证金为0的分类提交，验证无缴费步骤直接完成

**安全：**
24. store_name 含 SQL 注入 → 【抽样代表字符串字段注入】
25. 篡改 seller_name 越权提交他人入驻（用买家A的session，seller_name传买家B的账号）

### 抽样标注汇总

| 抽样项 | 代表参数 | 等价类范围 | 原因 |
|---|---|---|---|
| 空值-地区ID类 | province_id | province_id / city_id / district_id | 走同一套地区校验逻辑 |
| 非法值-地区ID类 | province_id | province_id / district_id | 同上 |
| 类型错误-地区ID类 | province_id | province_id / city_id / district_id | 同上 |
| 参数缺失 | company_name | 所有必填参数 | isset 检查走同一套逻辑 |
| SQL注入 | company_name | 所有字符串文本字段 | 注入防护通常是全局中间件 |
| XSS注入 | company_name | 所有字符串文本字段 | 同上 |
| Step3 ID类型错误 | storeclass_id | storeclass_id / store_class | 都是int类型转换 |
| Step3 参数缺失 | storegrade_id | 所有必填参数 | isset 检查走同一套逻辑 |
| Step3 SQL注入 | store_name | seller_name / store_name | 全局防护 |
| Step2 参数缺失 | settlement_bank_account_name | 所有必填参数 | isset 检查 |
| Step2 SQL注入 | settlement_bank_account_name | 所有字符串字段 | 全局防护 |
