# 3. 外卖浏览与交易链路（附近商家 / 店铺 / 商品 / 购物车 / 结算 / 下单）

## 3.1 定位（前端 + Cookie）
- 使用百度地图 JS API（ak=QMCCTcIV28j9WXXk4YIUDOuYHCgzMNnE）：`BMap.Geolocation` 定位、`Geocoder` 逆地址、地图选点/关键词搜索。
- 选定坐标后写入 Cookie：`longitude`、`latitude`、`pos_city`、`pos_district`（有效期约30天），并调用 `change_center(lng,lat)` → `get_store`。
- 测试要点：拒绝定位、经纬度为空/越界（>180/>90）、境外坐标、cookie 篡改、切换城市。

## 3.2 附近商家列表（核心 JSON）
- URL：`GET /index.php/home/Shopnearby/get_Own_Store_List`
- 鉴权：否
- Query：

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| longitude | decimal | 是 | 定位经度 |
| latitude | decimal | 是 | 定位纬度 |
| storeclass_id | int | 是 | 店铺分类ID，0=全部分类 |
| page | int | 否 | 滚动分页（more_store 加载下一页） |

- 返回：JSON 数组（注意是数组，无 code 外层），按距离排序，元素字段：
  ```json
  [{"store_id":9,"store_name":"吃饭啦","is_platform_store":0,
    "store_phone":null,"store_longitude":"106.559476","store_latitude":"29.556933",
    "area_info":"重庆 重庆市 南岸区","store_address":"重庆市南岸区",
    "store_logo":"http://.../default_store_logo.jpg","store_banner":null,
    "distance":0,"goods_list":[]}]
  ```
  - `distance` 距定位点直线距离（km/米，见 3.7）；`is_platform_store` 1=平台自营；`goods_list` 店内推荐商品。
- 测试要点：经纬度边界、分页 page 越界、分类不存在、空结果、距离排序正确性、下架/歇业/到期店铺是否过滤。

## 3.3 店铺详情（页面，服务端渲染）
- URL：`GET /index.php/home/Store/index/store_id/{id}.html`
- 展示：店铺名/Logo/横幅、起送价、配送费、平均送达速度、营业时间（如 08:00-21:00）、评分、收藏、店内分类。
- 全部商品：`GET /index.php/home/store/goods_all/store_id/{id}.html`
- 收藏店铺：`javascript:collect_store('{store_id}','count','store_collect')`（AJAX）
- 测试要点：不存在/已关闭/到期店铺、营业时间段外是否可下单、起送价与配送费展示。

## 3.4 商品详情（页面 + 规格/销量/咨询片段）
- URL：`GET /index.php/home/goods/index/goods_id/{id}.html`
- 规格列表（多规格 SKU）：`GET /index.php/home/goods/getspeclist.html?goods_commonid={commonid}` → `{"code":10000,"result":{...规格...}}`
- 销售记录片段：`GET /index.php/home/goods/salelog/goods_id/{id}/store_id/{sid}.html`（HTML 片段）
- 购买咨询片段：`GET /index.php/home/goods/consulting/goods_id/{id}/store_id/{sid}.html`
- 页面含：价格/促销价、库存 goods_stock、销量、规格、评价 Tab、加购与立即购买按钮。
- 测试要点：goods_id 非法/下架/删除、库存为0、多规格切换价格与 SKU、价格与库存一致性。

## 3.5 购物车
- 加入购物车（实测 POST 为准）：`POST /index.php/home/cart/add.html`
  - Content-Type：`application/x-www-form-urlencoded`；鉴权：是（未登录/店主买本店会被拒）
  - Body：

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| goods_id | int | 是 | 商品ID（单规格即 goods_id；多规格为具体规格 SKU 的 goods_id） |
| quantity | int | 是 | 本次加入数量 |
| store_id | int | 是 | 店铺ID |

  - 成功：`{"state":"true","num":1,"amount":"25.00"}`（state 字符串、num=购物车种类数、amount=合计金额）
  - 重复加购已在购物车的商品：`{"state":"false"}`（数量仍以购物车为准，需走改数量）
  - 店主购买自己店铺商品：`{"msg":"不能购买自己店铺的商品"}`
- 删除购物车项：`GET /index.php/home/Cart/del.html?cart_id={cart_id}`
  - 成功：`{"state":"true","quantity":0,"amount":"0.00"}`（quantity=删除后剩余数量、amount=剩余合计）
- 店铺购物车（右侧/店内）：`GET /index.php/home/store/getcartlist.html?store_id={sid}`
  - 返回 `{"code":10000,"result":{"cart_list":[{"cart_id":91,"buyer_id":161,"store_id":15,"store_name":"O2O南岸测试餐厅","goods_id":79,"goods_name":"测试-招牌黄焖鸡米饭","goods_price":"25.00","goods_num":1,"goods_image":null}],"cart_amount":25}}`
  - 不带 store_id 时返回 HTML 页面而非 JSON（必须带 store_id）。
- 右侧购物车 HTML：`GET /index.php/home/cart/ajax_load/type/html.html`
- 改数量：前端 `change_cart_quantity` → 复用 cart/add（quantity 为新总数；减到 1 再减走 del）。
- 测试要点：未登录加购、数量>库存、负数/0/超大数量、跨店购物车、店主买本店、规格 goods_id 与普通 goods_id 混淆、并发加购库存扣减、删除后金额/数量回算。

## 3.6 结算第一步（确认订单页）
- 进入：立即购买 buynow 设置 `#cart_id=goods_id|quantity` 后 POST `/index.php/home/buy/buy_step1.html`，表单字段 `cart_id[]=goods_id|数量`；购物车结算传 `cart_id[]=cart_id|数量`。
- 鉴权：是（未登录跳登录并带 ref_url 回跳）。
- 拦截规则（dispatch_jump 错误页，实测）：
  - 商品不存在/下架：“商品已下架或不存在”
  - 店铺未开启 O2O 配送：“店铺[xxx]不支持配送”（后台店铺 `store_o2o_support=0`）
- 结算页表单 `#order_form`（见 3.8），并加载：
  - 收货地址列表片段：`GET /index.php/home/Buy/load_addr.html`（HTML，radio，含地址55；“使用新地址” value=0）
  - 删除结算页地址：`GET /index.php/home/Buy/load_addr/id/{id}.html`（delAddr，删除后重载）
  - 新地址表单片段：`GET /index.php/home/Buy/add_addr.html`；提交 `POST /index.php/home/Buy/add_addr.html`
  - 发票列表：`GET /index.php/home/Buy/load_inv.html`；新增发票 `POST /index.php/home/buy/add_inv.html`

## 3.7 配送距离校验（下单关键业务规则）
- URL：`GET /index.php/home/Buy/calc_distance.html`
- Query：`store_ids={店铺id,多个逗号分隔}`、`addr_id={收货地址id}`
- 返回：`{"state":true,"msg":"","data":[]}` 可配送；
  超限：`{"state":false,"msg":"您的地址12440933m超出绿叶水果的配送距离100m","data":[]}`
- 规则：按店铺经纬度与收货地址经纬度算直线距离，与店铺配置的“配送距离”比较；前端据此置 `ALLOW_ADDRESS`，提交订单前拦截。
- 测试要点：边界（恰好等于配送距离）、超1米、店铺无坐标、地址无经纬度、多店铺部分超范围、篡改 addr_id、伪造距离。

## 3.8 提交订单（第二步）
- URL：`POST /index.php/home/buy/buy_step2.html`（表单 `#order_form`）
- 鉴权：是；Content-Type：form-urlencoded
- 主要字段：

| 字段 | 说明 |
|---|---|
| addr / address_id | 选中的地址 radio / 地址ID（必填，前端校验 address_id 非空） |
| true_name/city_id/area_id/area_info/address/longitude/latitude/mob_phone/tel_phone | 使用新地址时的地址字段 |
| cart_id[] | `goods_id|数量`（立即购买）或 `cart_id|数量`（购物车），可多店多条 |
| pay_name | 支付方式，默认 `online`（在线支付）；货到付款等其他值以页面为准 |
| pay_message[{store_id}] | 各店铺订单备注 |
| order_from | 订单来源，PC=1 |
| ifcart | 是否来自购物车 |
| vat_hash | 表单令牌（防重复提交/CSRF，每次结算页变化） |
| invoice_id | 发票ID（可选） |
| pd_pay / rcb_pay | 预存款/充值卡支付勾选；勾选需校验支付密码 password_callback=1 |

- 前端提交校验 submitNext：ALLOW_ADDRESS（距离）、cart_id 非空、address_id 非空、支付密码；`SUBMIT_FORM` 防重复点击。
- 金额：前端 calcOrder 汇总=商品总额+运费(eachStoreFreight)−满送(eachStoreManSong)−代金券(eachStoreVoucher)；**最终以服务端 buy_step2 重算为准**。

### 3.8.1 实测请求体（店铺15 / 商品79 / 地址58，已真实抓包）
```
POST /index.php/home/buy/buy_step2.html
Content-Type: application/x-www-form-urlencoded
Cookie: 登录会话

cart_id[]=91|1&pay_message[15]=测试订单&order_from=1&ifcart=1&
pay_name=online&vat_hash=JRe6M7gzEK4hGdR-ZlzWzbXWGf&
address_id=58&buy_city_id=&invoice_id=
```
- `cart_id[]` 值格式为 `购物车ID|数量`（如 `91|1`）；立即购买时为 `goods_id|数量`。**只传 `91` 不带 `|1` 会报“所购商品无效”**。
- `pay_message[15]` 下标 15 为 store_id（按店留言）。
- `vat_hash` 一次性防重令牌，必须先用 3.6 的 POST buy_step1 换取，且同令牌重复提交/失败后再提会报“您已经下过单了”，需重新进结算页换取新令牌。
- 结算页自动选中默认地址（address_id=58），配送费 2 元、商品 25 元。

### 3.8.2 实测响应（⚠️ 当前测试环境阻断性缺陷，无法取得成功返回）
- 真实返回为 dispatch_jump **错误页**（HTTP 200，`.system-message .error`）：
  ```
  SQLSTATE[HY000]: General error: 1364 Field 'o2o_distributor_realname'
  doesn't have a default value  页面自动跳转 等待时间：3
  ```
- 跑腿发单（member_o2o_errand_order/add）同类报错：`Field 'o2o_distributor_id' doesn't have a default value`。
- 根因（测试结论）：该环境 MySQL 开启严格模式（STRICT_TRANS_TABLES），订单扩展表（外卖 `order_o2o`、跑腿 errand）的配送员字段 `o2o_distributor_id / o2o_distributor_realname` 为 NOT NULL 且无默认值；下单瞬间尚未派单，服务端 INSERT 未给这些字段赋值，导致整单失败。
- 已尝试且**均不能绕过**（用于回归验证）：关闭店铺自动派单、新增平台配送员、后台为店铺建配送员、下单时补传 `o2o_distributor_realname/o2o_distributor_id`（服务端不读客户端该字段）。
- 副作用：失败的下单会清空对应购物车项，但不生成订单（买家订单列表为空），属数据一致性缺陷。
- 成功态（pay_sn/order_sn、跳转支付页）在本环境**无法真实取得，文档不臆造**；待环境修复（给配送员字段加默认值/关闭严格模式/修复派单写入逻辑）后，按本请求体回归即可抓到成功返回。
