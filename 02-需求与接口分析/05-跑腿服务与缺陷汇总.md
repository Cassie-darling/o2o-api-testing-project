# 5. 跑腿 / 服务链路、阻断缺陷汇总与测试用例设计

## 5.1 跑腿（帮买/帮送）发单
- 发单页：`GET /index.php/home/member_o2o_errand_order/send.html`（form id=`member_o2o_errand_form`）。
- 提交：`POST /index.php/home/member_o2o_errand_order/add.html`（form-urlencoded），鉴权：是。
- Body：

| 参数 | 必填 | 说明 |
|---|---|---|
| o2o_errand_order_type | 是 | 订单类型（默认 1，帮送；帮买等以页面选项为准） |
| o2o_errand_order_pickup_region_id | 是 | 取件地区末级 area_id（南岸区=352） |
| o2o_errand_order_pickup_lng / _lat | 是 | 取件经纬度 |
| o2o_errand_order_pickup_address | 是 | 取件详细地址（单元/楼层/门牌） |
| o2o_errand_order_pickup_name / _phone | 是 | 取件人姓名/手机 |
| o2o_errand_order_deliver_region_id | 是 | 送达地区末级 area_id |
| o2o_errand_order_deliver_lng / _lat | 是 | 送达经纬度 |
| o2o_errand_order_deliver_address | 是 | 送达详细地址 |
| o2o_errand_order_deliver_name / _phone | 是 | 收件人姓名/手机 |
| o2o_errand_order_detail | 是 | 物品类型（如 文件/餐饮/药品） |
| o2o_errand_order_weight | 否 | 重量（kg） |
| o2o_errand_order_goods_price | 否 | 物品价值（快捷 selectPrice 50/100/500） |
| o2o_errand_order_appointment_time | 否 | 预约时间 |
| o2o_errand_order_check_receive | 否 | 勾选（保密配送等，checkbox） |
| o2o_errand_order_gratuity | 否 | 小费/打赏 |
| o2o_errand_order_remark | 否 | 备注 |

- 跑腿费由距离/重量/时段试算（页面 JS select-weight/openPrice），最终服务端重算。
- **实测响应（阻断）**：HTTP 200 返回 ThinkPHP System Error 调试页，核心异常：
  `SQLSTATE[HY000]: General error: 1364 Field 'o2o_distributor_id' doesn't have a default value`（7 queries, 1 write）。
- 跑腿订单列表：`GET /index.php/home/member_o2o_errand_order/index.html`；发件地址管理见 02 的 o2o_errand_type=1。
- 用例要点：取/送地址缺失、跨城/超配送范围、重量与物品价值边界、小费边界、预约时间（过去时间）、手机号校验、距离与费用试算一致性。

## 5.3 阻断性缺陷汇总（本次接口测试的关键发现，均真实可复现）

### BUG-1 配送类订单创建必失败（严重 / 阻断核心交易）
- 现象：
  - 外卖 `POST /home/buy/buy_step2.html` → `1364 Field 'o2o_distributor_realname' doesn't have a default value`。
  - 跑腿 `POST /home/member_o2o_errand_order/add.html` → `1364 Field 'o2o_distributor_id' doesn't have a default value`。
- 根因：MySQL 严格模式 + 订单扩展表配送员字段 NOT NULL 无默认值 + 下单 INSERT 未赋值（配送员本应在商家接单/派单阶段才确定）。
- 已排除的业务因素（均无效）：店铺自配送/平台配送切换、自动派单开关、平台配送员存在与否、为店铺建配送员、客户端补传配送员字段。
- 影响：无法生成任何外卖/跑腿订单 → 支付、订单状态流转、评价、退款、商家接单、配送员派单等下游全部无法走正向用例；且失败请求会清空购物车项（数据一致性 BUG）。
- 复现：买家登录 → 店铺15 加购商品79 → POST buy_step1 取 vat_hash → POST buy_step2（见 03 的 3.8.1）→ 必现。
- 修复建议（供开发参考，测试不改库）：①给 order_o2o/errand 表配送员字段设默认值或允许 NULL；②或关闭该连接严格模式；③或在下单 INSERT 显式写入空配送员值；④失败时回滚购物车，避免误清空。

### BUG-2 商家端配送员新增必失败（中）
- 现象：`POST /home/seller_o2o_distributor/add.html` 无论如何提交均 `{"code":10001,"message":"请选择状态"}`（前端默认已选 state=1，XHR 抓包确认请求体含该字段）。
- 影响：商家无法在商家端维护自配送员（当前只能由后台 admin/o2o_distributor/add 代建）。
- 修复建议：核对服务端接收字段名与前端 name（o2o_distributor_state）是否一致、是否漏取。

### 其他环境注意点
- 入驻页百度地图 ak 无效，弹 alert 冻结页面（影响坐标选择，测试可直接传经纬度字段）。
- 个人入驻强制 18 位营业执照号（产品上需确认是否符合个人入驻预期）。
- 卖家设置页“平台配送/外卖总开关”单选被模板注释，仅店铺自配送可选。
- 商家端无坐标编辑入口，坐标只能在入驻 Step1 写入（店铺3 因此坐标为空、无法下单）。

## 5.4 测试用例设计建议（按接口测试视角）
- 鉴权：未登录、买家/卖家/后台三类会话越权（改 order_id/address_id/store_id 访问他人数据）、会话过期、退出后回退。
- 参数校验：必填缺失、类型错误、长度边界、枚举越界、负数/0/超大金额与数量、特殊字符与 SQL/XSS 注入位。
- 业务规则：配送距离边界（等于/超 1 米/无坐标）、起送价、营业时间、库存扣减、地址选到末级区县、经纬度合法性。
- 幂等与防重：vat_hash 一次性令牌、重复提交 buy_step2、重复接单/取消/确认收货、刷新重放。
- 状态机：订单 state_new→pay→send→success→eval 的合法/非法跃迁，取消/退款在各状态是否允许。
- 数据一致性：下单失败回滚（当前 BUG）、取消后库存/优惠券/购物车回滚、金额服务端重算与前端展示一致。
- 并发：库存并发扣减、并发接单、同一订单重复支付。
- 兼容性：三类响应形态（JSON code 10000/10001、dispatch_jump、纯文本 true/false）分别断言。
